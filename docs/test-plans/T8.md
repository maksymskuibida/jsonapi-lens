# Test plan — T8 Pre-existing defects found by the production baseline

**What this task changes, in one paragraph.** Seven independent, pre-existing defects get fixed:
document values (dates/numbers) now format in the app's chosen language instead of the browser's
(D1); a malformed share link says so instead of claiming the page does not exist (D2); a document's
`<title>` survives a fragment traversal instead of reverting to the paste view's (D3); the
saved-documents modal's count no longer goes stale on delete (D4); five strings that silently stayed
English in German/Ukrainian now translate (D5); `npm test` no longer depends on the machine's locale
(D6); and a compound reference key in a caseless script (CJK, Kana, Hebrew, Arabic, Thai) is now
recognised (D7). None of these is a new feature — every case below is either "did the existing
behaviour become correct" or "did everything adjacent stay exactly as it was."

## Scope

- **In scope:** `src/format.ts`, `src/i18n/intl.ts`, `src/router.ts`, `src/seo.ts`,
  `src/render-resource.ts`, `src/render-value.ts` (not originally listed as this task's, but D5's
  `aria-label` fix and D1's `locale()` call site both live there and nowhere else touches it this
  wave), `src/i18n/{en,de,uk}.ts`, `src/json-index.ts` (D7's boundary regex only), `src/panels.ts`
  (D4 — see the ownership note in `docs/task-specs/T8.md`), `test/setup.ts` (D6), and the new/extended
  test files listed under "Tests that must exist" in the spec.
- **Out of scope:** `src/main.ts`, `src/render-document.ts`, `index.html`, `src/styles.css`,
  `src/exchange.ts`, `src/params.ts`, `src/headers.ts`, `src/cookies.ts`, `src/secrets.ts`,
  `src/store.ts`, `src/crypto.ts`, `src/share.ts`, `src/worker.ts`, `migrations/` — all owned by
  another task in flight this wave, or by a task already merged. The blank "Back to the document"
  view (pre-existing, `main.ts`'s to fix). `crypto.ts`'s own message content (correct; D6 is a test
  problem, not an app problem).

**Altitude matters more than count here.** Every case above that touches layout, scroll position or
"does this look right on screen" (1–3, 17, 24, 25) is verified **twice**: once by hand in a real
browser (recorded in `docs/evidence/T8.md`, which is the only place D1 can be seen at all — it needs
the browser's own language to differ from the app's, which `npm test`'s jsdom cannot represent), and
once automated at the function/render level, which is what actually gates the PR. No case in this
task asserts a pixel offset, a scroll position, or anything `test/browser/nav-scenarios.js` would be
needed for — none of the seven defects touch layout.

## Edge cases enumerated

**D1 — locale-dependent formatting**

- A date-only value stays on its UTC calendar day in `en`, `de` and `uk` — the sharp edge named in
  the task spec. Covered (case 5).
- An invalid date string, a non-finite number, and a number needing the 6-digit fraction cap are all
  unaffected by the locale fix. Covered (cases 6–8).
- No `Intl` object anywhere in `src/` is constructed outside `intl.ts`'s one factory. Covered (case
  9) with a test that plants the old defect and confirms it is caught.

**D2 — the damaged share-link message**

- The four pathname shapes the spec's table names: `/d/1:short`, `/d/1`, `/d/1:`,
  `/d/notanumber:secret`. Covered (cases 10–13).
- The 64-character upper bound T5 raised. Covered (case 15).
- No oracle: two different ids produce the identical message. Covered (case 16).

**D3 — the title fragment bug**

- The exact idempotent path that was broken (a document already open, only the fragment changes) —
  not just "load `/view#hash` cold," which a naive fix could pass while leaving the chip-click case
  broken. Covered (case 17, both the manual chip-click and case 18's cold reload).
- `robots`/`canonical` provably unaffected, since the fix only touches title/description. Covered
  (case 20).

**D4 — the stale count**

- Both the last-item case (the one observed) and a non-last deletion, which was never broken but is
  worth pinning down alongside the fix. Covered (cases 21–22).
- A rename, which must **not** change the subtitle, as a negative control on the same code path.
  Covered (case 23).

**D5 — untranslated strings**

- All three sub-bugs named in the spec: the four action buttons + tooltips, the `Included` label, and
  the value-row `aria-label`s. Covered (cases 24–26).
- Rendered DOM output is asserted, not just catalogue content — a missing key is already a typecheck
  failure, so the point of these tests is catching a render path that never called `t()`, or called
  it for the wrong thing (the exact shape of both original bugs).

**D6 — locale-independent tests**

- All three required locales, run and recorded, not just the two that were failing before the fix
  reached them. Covered (cases 27–29).
- A direct, permanent regression guard (`test/locale-independence.test.ts`) so this does not need a
  human to remember to re-run three locales by hand on every future change.

**D7 — the Unicode boundary**

- The positive case this task adds (a CJK compound key). Covered (case 30).
- Both negative cases the spec calls out by name, from `docs/DECISIONS.md` D4: an upper-case boundary
  letter, and a bare lower-case-`id` key with no separator. Covered (cases 31–32).
- The existing ASCII compound-key cases, re-asserted unchanged. Covered (case 33).

## What should NOT have changed

- The anchor/id scheme (`docs/DECISIONS.md` D1) — untouched; D7 only widens which *keys* are read as
  compound references, never how an id is minted.
- `robots`/`canonical` behaviour on any route — D3 only touches `title`/`description`.
- The accepted secret-length range (8–64 characters) and its own error messages
  (`shareErrors.secretLength`) — D2 adds a *router-level* message for a secret so malformed it never
  reaches that code at all; it does not change what makes a secret valid.
- Back/Forward, scroll restoration, row-expansion state — this task touches no layout, no history
  entry shape, and no DOM offset above the fold.
- The existing ASCII compound-key detection (`user_id`, `user-id`, `userId`, `userIDs`) and the
  existing `valid`/`is_valid`/bare-key protections from D4 — D7 only adds `\p{Lo}` to one character
  class.
- Every other string in `en`/`de`/`uk` besides the five D5 groups.
- `crypto.ts`'s/`share.ts`'s own behaviour and error content — D2 and D6 both touch code that calls
  into them, but neither changes what they do.
