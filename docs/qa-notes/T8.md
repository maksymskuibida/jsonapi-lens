# QA notes — T8 Pre-existing defects found by the production baseline

Written for someone who **cannot read the code** and has never seen this change.

**This task fixes seven small, independent, pre-existing defects.** None is a new feature — every
one is "something the app already claimed to do, that it was not actually doing." Five were found by
a baseline pass against production before this release; two more were found afterwards. You are
checking that each one is now actually true, and that nothing next to it broke.

## What changed, observably

1. **Dates and numbers inside a document now follow the app's language, not your browser's.** Set
   the app to a language your browser is *not* set to (see "Where to exercise it" below — this is
   the one case in this task where your own browser's language setting matters). Expand a resource
   with a date or number attribute. It should render in the app's language — English dates like
   `Sep 14, 2026`, German like `14.09.2026`, Ukrainian with a Cyrillic month abbreviation and no
   comma as a thousands separator — regardless of what your browser itself is set to. Before this
   task, it always rendered in your browser's language, no matter what the app said.

2. **A badly broken share link now says so.** Visiting a URL shaped like `/d/<some number>` with
   nothing after it, or with a secret that is obviously too short, now shows a toast saying the link
   looks damaged and names the expected shape (`/d/<id>:<secret>`), instead of a generic "no page
   here." A share link with a secret merely one character short (or a wrong secret against a real
   id) is unchanged — it still correctly says the link could not be decrypted. **Do not try to tell
   whether a specific share id exists from these messages** — that is deliberate; the app cannot know
   and does not pretend to.

3. **A document's tab title no longer reverts when you follow a link inside it.** Open any document,
   click a relationship chip (or any link that jumps to another resource in the same document). The
   browser tab's title should keep naming your open document the whole time. Before this task, it
   would flip to the generic app title ("jsonapi-lens — follow the pointer") the moment you clicked
   anywhere inside the document.

4. **The "Saved documents" count no longer goes stale.** Save one document, open "Saved documents,"
   delete it without closing the dialog. The subtitle under the title should update immediately to
   say the library is empty, not keep showing the old count.

5. **Five more strings translate in German and Ukrainian.** Switch language to German or Ukrainian,
   expand a resource: its four small action buttons (raw/copy/path/link, and their tooltips) should
   be in that language. The overview stat currently labelled "Included" should also be translated
   (matching its neighbours: Shape, Resources, Types, Relationships, Size). These were previously
   left in English in both non-English languages.

Two more fixes have **no UI at all** and nothing to click:

6. `npm test` used to fail on a machine (or CI runner) configured for German or Ukrainian — not
   because the app was broken, but because five test assertions happened to hardcode English. This
   is now fixed and cannot be exercised through the app; it is verified by re-running the test suite
   under different locale settings (see the evidence file).
7. A payload key written in a script with no upper/lower case at all (Japanese, Chinese, Hebrew,
   Arabic, Thai) — e.g. a key like `顧客Id` — is now recognised as a reference the same way `userId`
   already is. This only shows up if you paste a plain-JSON (not JSON:API) document containing such a
   key; there is no sample document that demonstrates it, so it is not practical to exercise by hand
   without constructing one.

## Where to exercise it

- **Environment:** `preview_start { name: "jsonapi-lens" }` — the dev server on port 5178.
- **Surface:** the language switcher (topbar), any loaded document's expanded resources, the "Saved
  documents" panel, and a hand-typed `/d/…` URL.
- **Important for item 1 only:** the bug is *only visible* when your browser's own language differs
  from the app's chosen language. If your browser and the app happen to agree, item 1 will look
  correct either way and proves nothing. Change your browser's own language setting (or the OS
  language, whichever your browser follows) to something other than the app's `?lang=`/language
  switcher choice before testing item 1 specifically.
- **Note:** `/api/*` is not served by the dev server, so a *real* share link (item 2's "correct,
  unchanged" case — a valid-shaped link against a real id) cannot be created or opened locally. The
  *damaged*-link message (item 2's actual fix) needs no network request at all and works fine
  locally — that is the point of the fix.

## How to exercise it

1. Load the "Article feed" sample. Note the `published at` date on the first article.
2. Set the app's language to English (`?lang=en` or the switcher). With your browser's own language
   set to something other than English (see above), confirm the date still reads in English format.
   Repeat with the app set to German, then Ukrainian, confirming each renders in *its own* format
   regardless of your browser's setting.
3. Type `/d/1` into the address bar and press enter. Confirm the toast names a damaged link and
   shows the expected `/d/<id>:<secret>` shape, not "no page at /d/1."
4. Type `/d/1:short` (any string under 8 characters after the colon). Confirm the same message.
5. Type `/d/notanumber:whatever` and confirm you get the *ordinary* "no page here" message instead —
   this path is deliberately not treated as a share link.
6. Load any sample, click a relationship chip that resolves. Watch the browser tab title through the
   click — it should keep naming the open document at every point, never flashing to the generic app
   title.
7. Save a document (`s`), open "Saved documents" (`l`), delete it. Confirm the subtitle updates in
   place, without closing and reopening the dialog.
8. Switch language to German, then Ukrainian: expand a resource and check the raw/copy/path/link
   button row and its tooltips are in that language; check the overview stat currently labelled
   "Included" is also translated.

## Test data needed

The built-in "Article feed" sample covers items 1, 3 and 6. Items 3–5, 7 and 8 need no particular
payload — any loaded document or the empty-library state will do.

## What should NOT have changed

- Back and Forward return the content you were looking at to the same place on screen.
- A row that was expanded is still expanded, and still expands when clicked.
- Nothing in the network log carries document content.
- A share link with a secret that is *merely* wrong (right length, wrong characters) against a real
  id still says "could not be decrypted" — only a link short enough to fail the basic shape check
  gets the new message.
- The overview counters (Resources, Types, etc. at the top of the document) — these were already
  correct before this task; only values *inside* the document (attributes, `meta`) were affected by
  the locale bug.

## Known limitations

- **D6 and D7 (the test-suite locale fix and the CJK reference-key fix) have nothing to click** —
  they are verified by the automated suite and, for D6, by re-running it under different `LANG`
  settings, recorded in `docs/evidence/T8.md`. There is no UI action that demonstrates either.
- **The private-window/storage-blocked case is still not tested** — carried over from the baseline
  report as a known gap in the QA harness, not something this task attempted.
- I did not verify item 1 against a live production deploy — only against the local dev server. The
  evidence file's NOT OBSERVED section says so explicitly.
