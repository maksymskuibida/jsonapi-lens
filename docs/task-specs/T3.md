# Task specification — T3: Importers

> Contract level, not line level. Depends on **T2** (the `Exchange` model and `mergeExchange`).

## Outcome

You stop typing. Paste what you already have — a cURL command, a raw HTTP exchange, a URL, a HAR
entry, or a **JSON transport-log record** — and the form fills itself. Paste the second half later
and it merges into what is already there rather than replacing it.

## Interface

Every importer has the same shape and no other privileges:

```
Importer {
  id: string
  detect(text: string): Detection | null      // never throws
  parse(text: string): ImportResult           // may throw ImportError
}

Detection   { id, confidence, summary }        // "cURL · GET · 3 headers · 6 params"
ImportResult { exchanges: Partial<Exchange>[], warnings: string[] }
```

Import is **always a merge**: the result goes through T2's `mergeExchange` into the current draft.
There is no second write path. An importer that yields more than one exchange presents a picker
first.

## Behaviour

### Detection, then an offer — never a silent replacement

Pasting runs every `detect` and takes the highest confidence. The paste view names what it found
before importing (`cURL recognised · GET · 6 params · 2 headers · 1 secret masked`) and says whether
it will **fill** an empty draft or **merge into** an existing one, listing which fields it would
overwrite. Overwriting a field the user typed by hand always asks.

### The importers

**1 · cURL.** `-X`/`--request`, `-H`/`--header`, `-d`/`--data`/`--data-raw`/`--data-binary`,
`--data-urlencode`, `-F`/`--form`, `-b`/`--cookie`, `-u`/`--user` (→ a Basic header),
`--compressed`, `-G` (body params become query params). Shell quoting — single, double, `$'…'`,
backslash continuations, and the `^` continuations Windows devtools emits. An unknown flag is a
**warning, not a failure**: parse what you understood and say what you skipped.

**2 · Raw HTTP request.** Request line, headers, blank line, body. `Host` promotes to the URL's
origin when the request line is a path.

**3 · Raw HTTP response.** `HTTP/1.1 200 OK`, headers, blank line, body. Status, headers and
document in one paste — the fastest path to a complete exchange when paired with a request.

**4 · A bare URL.** The common quick case. Query string decoded through T2's decoder.

**5 · HAR.** One entry, or a picker over many. Method, URL, query, headers, cookies, request and
response bodies, status, and timings.

**6 · JSON transport log.**

A widely-used shape rather than one product's: a JSON object whose `info` member is a serialised
Python `logging` record — `levelname`, `levelno`, `pathname`, `filename`, `module`, `lineno`,
`funcName`, `created`, `msecs`, `relativeCreated`, `thread`, `threadName`, `processName`,
`taskName`, `asctime`, `exc_info`, `exc_text` and `stack_info` are all documented `LogRecord`
attributes — with HTTP transport fields written alongside them, and a sibling `context` member
carrying ambient request metadata. Any service that logs its outbound calls through a JSON handler
produces something of this shape.

It earns its place because `info.response_data` is very often **exactly the JSON:API document this
tool exists to read**, and unpacking it by hand is the work this importer removes.

Detected by `info.message_type === "transport_logging"`, or failing that by `info.event_type`
ending `_request` together with `info.url` and `info.http_method`. Two record kinds, and either may
arrive alone:

| Record | Recognised by | Contributes |
|---|---|---|
| **started** | `info.funcName === "log_start"`, `info.msg` ending `request started`, or the presence of `request_headers` | `request` |
| **finished** | `info.funcName === "_log_response"`, `info.msg` ending `request finished`, or the presence of `response_status_code` | `response` |

Field mapping:

| From | To |
|---|---|
| `info.http_method`, `info.url` | `request.method`, `request.url` — a **started** record also fills these on a finished one |
| `info.request_params` | `request.query` — may be `null`, an already-decoded object, or a query string |
| `info.request_data` | `request.body` — may be `null`, an object, or a string |
| `info.request_headers` | `request.headers` |
| `info.response_status_code` | `response.status` |
| `info.response_headers` | `response.headers` |
| `info.response_data` | `response.body` — **usually the JSON:API document**, and the reason this importer matters |
| `info.elapsed_time` | `response.elapsedMs`, ×1000 — it is seconds as a float |
| `info.created` / `info.asctime` | the record's timestamp |
| `info.provider`, `info.provider_method`, `info.levelname`, `info.instance_name`, `info.applevel` | `origin` — whichever are present; all are optional |
| `context.*` | `origin.context` — rendered as a collapsed lens, not a wall of text |

**Correlation.** Two records pair into one exchange when `context.correlation_id`, `info.url` and
`info.http_method` all match and one is *started* while the other is *finished*. A matching
`correlation_id` with a **different** url or method is a different call in the same trace — a real
and common case, since one inbound request fans out to several providers. Pasting an array or an
NDJSON stream of records therefore groups by `(correlation_id, url, method)`, pairs each group, and
presents a picker listing method, path, status and elapsed time. Order does not matter: a finished
record pasted before its started record merges the same way.

**`context` is worth surfacing, not hiding.** A correlation id, a task name, the calling service
and its version, an actor, and a feature-flag list are the first things anyone asks when an
outbound call misbehaves. `context` has **no fixed schema** — treat it as a plain-JSON lens (T1)
rather than a set of named fields, so an unfamiliar key is rendered rather than dropped. Render an
array-valued member such as a flag list as a collection, since these routinely run to 40+ entries.

### Secrets and personal data — the part this importer makes urgent

A transport-log record carries more than a credential. In practice these contain an **actor email
address**, a **client IP**, a **user agent**, **host and instance names**, and **service versions**.
T2's masking covers `api-key` and `authorization`; this task extends the redaction offer to cover
email-shaped and IP-shaped values anywhere in `origin`, on the same terms: offered by default on
Copy, Download and Share, with a count of what is dropped, never silently.

**No real log record may be committed to this repository, from any system.** It is public — the
site, the code and the test data. Every fixture here is **synthesised**: the same structure and key
names, with invented service and host names, addresses on `example.com`, and documentation-range
IPs (`192.0.2.0/24`, RFC 5737). A fixture carrying a real address, a real hostname, or an
identifier traceable to any organisation is a **blocker**, not a nit.

Be precise about what enforces which half: `test/hygiene.test.ts` fails the build on an address
outside the reserved example domains and on an IP literal outside the documentation ranges, and on
**nothing else**. Host names, service names and flag names are caught by the reviewer, not by a
check — deliberately, since a denylist of names would have to contain them. Adding a fixture in a
format the gate's extension list does not cover means adding that extension in the same change.

## Error and edge cases

| Case | Expected |
|---|---|
| Text no importer recognises | Falls through to T1's shape detection; if that fails too, today's parse error |
| Two importers both matching | Higher confidence wins; the offer names which and lets the other be chosen |
| cURL with an unknown flag | Imported, with a warning naming the flag |
| cURL with unbalanced quotes | `ImportError` with the position, and the paste box keeps the text |
| cURL with `-G` and `-d` | Body params become query params |
| Raw HTTP with `\r\n` or bare `\n` | Both accepted |
| Raw HTTP with no blank line | Treated as headers only, no body, with a warning |
| Raw HTTP with a chunked body | Chunk sizes stripped; a warning if reassembly is not clean |
| A HAR with 400 entries | Picker, not a 400-way merge; paged if needed |
| A HAR entry with a base64 `content.encoding` | Decoded; binary shown as a size, not as text |
| Transport log: an `info` with no HTTP fields at all (an ordinary log line) | Not detected as an exchange; falls through to T1's plain-JSON reading |
| Transport log: started only | Request-only exchange, method and url present |
| Transport log: finished only | Response-only exchange, and method and url still filled from `info` |
| Transport log: finished pasted before started | Merges identically; order is irrelevant |
| Transport log: same `correlation_id`, three different urls | Three exchanges in the picker, not one merged mess |
| Transport log: `request_params: null`, `request_data: null` | Absent, not an empty object — "the server sent nothing" and "the server sent `{}`" are different |
| Transport log: `elapsed_time` present | Rendered in ms; `0.4785615630025859` reads as `479 ms` |
| Transport log: `response_data` a JSON:API document | Full resource treatment, response scopes (`r_`, `g_`) |
| Transport log: `response_data` a string of JSON | Parsed one level and rendered as a lens, with the double encoding named |
| Transport log: `exc_info` / `exc_text` non-null | Surfaced prominently — a traceback is the answer to the question being asked |
| An importer's `detect` throwing | Impossible by contract; a test asserts every `detect` returns `null` on hostile input rather than throwing |
| Importing over a hand-typed field | Asks before overwriting, naming the fields |
| Hostile values anywhere in an imported record | Rendered as text; `javascript:`/`data:` URLs are not `href`s |

## Out of scope

- The cross-checks between request and response — **T4**.
- Kronos or any log-search integration. This tool never makes a network call to fetch a record; you
  paste it.
- A trace view showing every call in one `correlation_id` as a timeline. The picker is in scope; the
  timeline is a later task.
- `Copy as fetch` / axios / Python-`requests` snippets. Worth doing once these six work; not now.

## Acceptance criteria

- [ ] Each of the six importers fills the form from a realistic input, and the form remains editable afterwards.
- [ ] The paste view names what it detected, and whether it will fill or merge, before anything changes.
- [ ] Pasting a *started* record then a *finished* record yields one complete exchange; the reverse order yields the same one.
- [ ] Pasting a stream whose records span three URLs yields a picker of three, each labelled with method, path, status and elapsed time.
- [ ] A transport log whose `response_data` is JSON:API renders as resources with relationship links.
- [ ] `exc_text` on a failed call is visible without expanding anything.
- [ ] Redaction covers the actor email and the customer IP as well as credentials, with a count, on Copy, Download and Share.
- [ ] No fixture in the repository contains a real email address, a real hostname, or any identifier traceable to a real organisation. The addresses and IP literals are enforced by `test/hygiene.test.ts`; the names are a reviewer check, and the reviewer is told so.
- [ ] Every new string exists in `en`, `de` and `uk`.
- [ ] `docs/evidence/T3.md` records a browser run at the branch-head SHA it was performed at.

## Tests that must exist

- [ ] Every `detect` returns `null` rather than throwing, over a corpus including empty string, binary bytes, a 5 MB single line, and a deeply nested object.
- [ ] cURL: the exact string Chrome devtools emits for a GET with headers, and the one it emits for a POST with `--data-raw`, both round-trip to the expected exchange.
- [ ] cURL: single, double and `$'…'` quoting; `\` and `^` line continuations; `-G` moving body params to the query.
- [ ] Raw HTTP request and response, with `\r\n` and with bare `\n`.
- [ ] Transport log: a synthesised *started* record maps every field in the mapping table.
- [ ] Transport log: a synthesised *finished* record maps every field, and `elapsed_time` converts to ms.
- [ ] Transport log: started+finished merge in both orders to an identical `Exchange`.
- [ ] Transport log: `request_params: null` yields an absent query, distinguishable from `{}`.
- [ ] Transport log: three records sharing a `correlation_id` across two URLs group into two exchanges.
- [ ] `test/hygiene.test.ts` reaches every fixture this task adds — if a `.har` fixture is added, the glob's extension list covers `.har`. Assert the file appears in the scanned set, not merely that the suite is green: a glob that silently misses a file reports a pass.
- [ ] Redaction: an imported record's actor email and customer IP do not appear in the Copy payload, the Download payload, or the sealed share blob — asserted against the actual bytes.
- [ ] Hostile values in an imported URL, header and param render as text.
