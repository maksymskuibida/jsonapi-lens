# Task specification — T2: The exchange — model, form and review

> Contract level, not line level. Depends on **T1** (a request or response body is often plain JSON,
> or not JSON at all).

## Outcome

A response stops being the whole story. You can attach the request that produced it — URL, method,
query parameters, headers, cookies and body — plus the response's own status, headers and cookies,
and review the whole exchange on one page.

Everything is **optional and independently fillable**. You can enter a request alone, a response
alone, or either in part, and come back and extend it later without starting again. The form is the
canonical way in; T3 adds importers that write through the same path.

## Interface

```
Exchange {
  request?:  RequestPart
  response?: ResponsePart
  origin?:   OriginMeta      // where this exchange came from, when imported
}

RequestPart  { method?, url?, query?: ParamSet, headers?: HeaderSet,
               cookies?: CookieSet, body?: BodyPart }
ResponsePart { status?, statusText?, headers?: HeaderSet,
               cookies?: SetCookieSet, body?: BodyPart, elapsedMs? }
BodyPart     { raw: string, contentType?: string, lens?: Lens, form?: ParamSet }
```

`Lens` is T1's union, so **a body is rendered by the same machinery as a document** — a JSON:API
request body gets the full resource treatment, a plain-JSON body gets the tree and the inferred
graph, and anything else is text.

Every part is optional at the type level, not merely by convention. `mergeExchange(base, incoming)`
folds one partial into another and is the single write path: the form uses it, and so will every
importer in T3.

## Behaviour

### The form — each field separated

One field per thing, nothing bundled into a textarea that has to be re-parsed:

| Group | Fields |
|---|---|
| Request | method (select), URL, query parameters (name/value rows), headers (name/value rows), cookies (name/value rows), body (+ content type) |
| Response | status, status text, headers (name/value rows), `Set-Cookie` entries, body (+ content type), elapsed time |

- **URL and the query table stay in sync, both ways.** Typing a query string into the URL fills the
  table; editing the table rewrites the URL. The table is the truth; the URL is a rendering of it.
- A row may be **disabled** rather than deleted, so a parameter can be taken out of consideration
  without losing it.
- Adding a header called `Cookie` moves its contents into the cookie rows, and the same for
  `Set-Cookie` on the response. A cookie is not a header in the review even though it arrives as one.
- The form is **never a required step.** With no request entered, the view is exactly today's
  document view.

### The review — three modes

A segmented control: **Response** · **Request** · **Both**. `Both` is the default when both parts
exist; a single part selects its own mode and the control is hidden.

Above the overview sits a band, collapsed to one line: method, URL, status, and counts —
`6 params · 4 headers · 1 cookie · 3 findings`. Open, it is the full review: origin and path split
out, the parameter table, headers, cookies, and each body as its own lens.

### Parameters — every encoding, named per parameter

One decoder for the query string **and** for an `application/x-www-form-urlencoded` body.

| Encoding | Wire | Decodes to |
|---|---|---|
| Repeated key | `a=1&a=2` | `[1,2]` |
| Bracket list | `a[]=1&a[]=2` | `[1,2]` |
| Indexed | `a[0]=1&a[1]=2` | `[1,2]` |
| Comma | `a=1,2,3` | `[1,2,3]` |
| Space / pipe delimited | `a=1%202`, `a=1\|2` | `[1,2]` |
| Bracket object, nested | `a[b]=1`, `a[b][c]=1` | `{b:1}`, `{b:{c:1}}` |
| Dot path | `a.b=1` | `{b:1}` |
| JSON in a value | `a={"b":1}` | `{b:1}` |
| Base64url JSON | `cursor=eyJvIjoyNX0` | `{o:25}` |

**Ambiguity is shown, never guessed away.** `a=1,2` is a list in JSON:API and the literal string
`"1,2"` in Express. The decoder renders its reading, **names the convention it inferred**, offers
the alternative per parameter, and always keeps the raw wire value one row away.

JSON:API parameters are first class: `include` renders as the tree it describes, `fields[type]` as a
named fieldset, `sort` with direction per field, `page[*]` and `filter[*]` decoded through the
nesting rules above. These are the checks T4 consumes.

### Headers, cookies, and secrets

- Header names are case-insensitive and preserved as typed; duplicates are kept in order, because a
  repeated `Set-Cookie` is normal and a repeated `Content-Length` is a finding.
- Cookies parse into name, value and attributes (`Domain`, `Path`, `Expires`, `Max-Age`, `Secure`,
  `HttpOnly`, `SameSite`), with an expiry shown relative to now.
- **Masked by default:** `authorization`, `proxy-authorization`, `cookie`, `set-cookie`,
  `x-api-key`, `api-key`, `x-auth-token`, and any value matching a credential shape (a JWT, a long
  base64/hex run, `sk_`/`pk_`-prefixed keys). Click to reveal, one at a time.
- **A `Bearer` JWT is decoded locally** — header and payload, no verification, never a network call
  — and `exp` is rendered relative to the response's own timestamp when there is one, so "expired
  four minutes before this call" is readable at a glance.
- **Redaction survives the exits.** Copy, Download and Share each offer redaction by default, with a
  count of what is being dropped, and never silently. A mask that a Copy button walks around is not
  a mask, and this is checked on both write paths.

### Anchors

Per [DECISIONS.md D1](../DECISIONS.md), request-side ids use their own two-character scopes —
`q_` for a request field, `b_` for a resource in the request body, `d_` for a plain-JSON node in it.
Response ids keep `r_`, `g_` and `n_` **unchanged**, so every existing fragment keeps working.
No id is minted outside `ident.ts`.

### Persistence and share

`StoredDocument` and `LibraryEntry` gain an optional `exchange`. IndexedDB goes to version 3;
`onupgradeneeded` already creates only missing stores, and a v2 record is a response-only exchange,
so old records keep opening. `SharePayload` gains the same optional field — an old ciphertext still
decrypts, because the field is absent rather than wrong.

## Error and edge cases

| Case | Expected |
|---|---|
| No request at all | Today's view exactly; no band, no segmented control |
| Request only, no response | Request mode, no response section, no diagnostics |
| Response only | Today's view plus a status and response headers |
| URL with no scheme (`api.example.com/x`) | Accepted; `https` assumed and the assumption shown |
| URL that will not parse at all | Kept as text, query table empty, a note saying why |
| Duplicate query key with different encodings (`a=1&a[]=2`) | Both shown, conflict named, neither silently wins |
| Empty parameter value (`a=`) vs valueless (`a`) | Distinguished — empty string versus present-with-no-value |
| Percent-encoded and `+`-encoded spaces | Both decoded; the raw form stays available |
| A parameter value that is 100 kB | Truncated in the row with the full value one click away |
| `Content-Length` disagreeing with the body's byte length | Kept as given; flagged in T4, not silently corrected |
| Body declared JSON but not parseable | Shown as text with the parse error and its line |
| Body that is JSON:API | Full resource treatment under the `b_` scope; no collision with the response |
| Request and response bodies **both** JSON:API with the same `type:id` | Both render; both anchor; nothing collides. This is the case D1 exists for |
| `Set-Cookie` repeated four times | Four cookie entries, in order |
| Malformed `Set-Cookie` | Name and value kept, unparseable attributes listed verbatim |
| An expired JWT | Decoded, `exp` shown relative to the response timestamp, marked expired |
| A JWT that is not three base64url segments | Not decoded; shown as an opaque masked value, no error |
| Hostile values in a URL, header name, header value, param name or param value | Rendered as text. `javascript:`/`data:` URLs are not `href`s |
| Sharing an exchange holding a secret | Redaction offered by default with a count; declining is explicit |
| A v2 IndexedDB record | Opens as a response-only exchange |
| A share link minted before this change | Decrypts and opens |

## Out of scope

- Importers of any kind — cURL, raw HTTP, HAR and JSON transport logs are **T3**.
- The cross-checks between request and response — **T4**.
- Sending the request. This tool never makes the call, and nothing here may open a network
  client connection outside `store.ts`/`share.ts`/`crypto.ts`.
- Editing the response body as a document.
- More than one exchange at a time.

## Acceptance criteria

- [ ] With no request entered, the document view is byte-for-byte the behaviour of today.
- [ ] Every field in the table above can be filled by hand, and the review renders what was entered.
- [ ] A partial exchange saves, reloads from IndexedDB, and can be extended without re-entering what was already there.
- [ ] Editing the query table rewrites the URL, and editing the URL refills the table.
- [ ] Each parameter row names the encoding convention it was read with, and offers the alternative.
- [ ] A request body that is a JSON:API document renders as resources, and no DOM id collides with the response's.
- [ ] `Authorization` is masked on arrival, reveals on click, and is redacted by default in Copy, Download and Share, each showing a count.
- [ ] A `Bearer` JWT shows `sub`, `iss`, `scope` and `exp`, with `exp` relative to the response timestamp.
- [ ] Back and Forward still return the content you were looking at to the same place on screen, with the band open and with it closed.
- [ ] Every new string exists in `en`, `de` and `uk`.
- [ ] `docs/evidence/T2.md` records a browser run at the branch-head SHA it was performed at, including the three view modes at 375px and 1440px, in both themes.

## Tests that must exist

- [ ] `mergeExchange` is associative over partials, and never discards a field present in the base and absent in the incoming.
- [ ] Every row of the parameter table decodes to the stated value, and re-encodes to a query string that decodes back to the same value.
- [ ] `a=1&a[]=2` reports a conflict rather than picking one.
- [ ] `a=` and `a` decode to distinguishable values.
- [ ] `include=legs.station,legs.operator` produces the include tree `legs → {station, operator}`.
- [ ] `filter[status][in]=booked,held` decodes to `{status: {in: ["booked","held"]}}` and names both conventions.
- [ ] Header lookup is case-insensitive; duplicate headers are preserved in order.
- [ ] Four `Set-Cookie` values parse to four cookies with their attributes.
- [ ] A JWT with `exp` in the past is marked expired; a non-JWT bearer value is not decoded and does not throw.
- [ ] Redaction: an exchange carrying `Authorization` produces no occurrence of the secret in the Copy payload, the Download payload, or the sealed share blob — asserted against the actual bytes.
- [ ] Anchor scopes: over a corpus of hostile `type`/`id` pairs, a request-body document and a response document sharing every identity produce **no** duplicate DOM id, and `parseDomId` recovers the right scope for each.
- [ ] A v2 IndexedDB record and a pre-change share payload both load.
- [ ] Hostile values in a URL, header name, header value, param name and param value all render as text; a `javascript:` URL is not rendered as an `href`.
- [ ] Browser scenario: with the band open, following a relationship and pressing Back returns the same content to the same place on screen, and a row that was expanded still expands.
