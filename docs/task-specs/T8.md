# Task specification — T8: Pre-existing defects found by the production baseline

> Contract level, not line level. Independent of T1–T7 in substance, but **runs after T1 merges**
> because it edits files T1 owns.

## Outcome

Five defects that are live on `https://jsonapi.mstool.dev` right now stop being live. None was
introduced by this release — they were found by a baseline pass run deliberately *before* deploying,
so that the post-deploy pass could tell a regression from a pre-existing condition. Fixing them is
the maintainer's standing instruction: anything that does not work gets fixed.

Every one was reproduced on production. The severities are the baseline report's.

---

## D1 · Values are formatted in the browser's language, not the app's — **high**

**Observed:** with the app explicitly set to English, and again to German, dates and numbers *inside
document values* rendered in the format of `navigator.languages` — Ukrainian, on the machine that
ran the pass. Reproduced in five independent places: resource attributes, top-level `meta`, and
error `meta`. Overview stat counters are unaffected.

**Why it is worse than it looks.** `src/i18n/intl.ts` exists *specifically* to fix this, and its
header comment says so:

> Before this existed the app called `toLocaleString()` with no locale, which reads the browser's
> setting — so a German UI on an American browser rendered `1,234 Ressourcen`. Numbers now follow
> the language the user chose, like the words around them.

That is true of the catalogue's counts and false of document values, because `src/format.ts` was
never migrated: `formatDate` still calls `toLocaleDateString(undefined, …)` and
`toLocaleString(undefined, …)`, and `NUMBER_FORMAT` at `src/format.ts:32` is
`new Intl.NumberFormat(undefined, …)`. **So a header comment is currently asserting a fix that half
the app never received**, which is its own defect under `docs/PROCESS.md` §6.

`NUMBER_FORMAT` is also constructed at **module scope**, which freezes it at load — the same trap
the codebase already documents for `t()`. A language switch reloads the page today, so this does not
bite yet; it would the moment that changed.

**Required:** every locale-dependent rendering of a document value goes through the chosen language.
`Intlish` in `intl.ts` is the existing home for "locale-dependent but not a translated string" —
extend it rather than adding a second mechanism. No `Intl` object is constructed at module scope. If
`intl.ts`'s header comment is still not fully true afterwards, correct the comment in the same diff.

## D2 · A malformed share link says "no page here" — **medium**

**Observed:** `/d/<id>:<secret>` with a secret shorter than 8 characters (tested at 7 and 5, against
a real 10) does not match `SHARE_PATTERN` at `src/router.ts:64`, falls through to
`{ kind: "unknown" }`, and is handled at `src/main.ts:1479` by toasting *no page here* and replacing
the URL with `/`.

**Correction to the baseline report**, which called this silent: it is not silent, it toasts. The
defect is that the message is **wrong**. A secret one character short matches the pattern, attempts
decryption, and correctly says the document could not be decrypted. So a link that is *slightly*
broken is diagnosed and a link that is *badly* broken is reported as a page that does not exist —
exactly backwards, and the user's next action ("was the link truncated?") is the one the message
sends them away from.

**Required:** a path shaped like a share link — `/d/<digits>` followed by anything — is recognised as
a share link. When the secret is malformed, say that the link looks truncated or damaged, name the
expected shape, and do **not** claim the page does not exist. Nothing about the accepted range for a
valid secret changes; T5 raised the practical upper bound to 64 characters and that stands.

**Do not introduce an oracle.** The new message must not distinguish "this id exists but your secret
is wrong" from "this id never existed" — that distinction is deliberately unavailable, and this
change must not leak it.

## D3 · `/view`'s title falls back to the paste view's whenever there is a hash — **low**

**Observed:** after following any relationship chip, or on any deep link, `<title>` and `og:title`
revert to the paste view's. `robots` and `canonical` stay correct, so this is cosmetic — but the
document title is what a browser tab and a bookmark show, and following a chip is the single most
common action in the app.

**Required:** the fragment does not change which page the head describes. `test/seo.test.ts` exists;
extend it.

## D4 · The saved-documents count goes stale on delete — **low**

**Observed:** deleting the last saved document with the modal open updates the list but leaves the
modal's subtitle count at its old value.

**Required:** the count is derived from what is rendered, not computed once when the modal opens.

> **Ownership note:** this is in `src/panels.ts`, which **T6** owns. If T6 has not merged, T8 takes
> it; if T6 is in flight, it takes it instead and T8 drops it. Whoever takes it says so in its PR
> body, and the other says it was dropped. Both fixing it is a conflict; neither fixing it is how a
> low-severity defect survives a release.

## D5 · Strings that do not translate — **low, and non-negotiable**

**Observed** in German and Ukrainian:

- the four per-resource action buttons — *raw*, *copy*, *path*, *link* — and their tooltips;
- the **Included** overview stat label;
- the attribute-copy buttons' `aria-label`.

Visible text and `title` for the attribute-copy buttons *do* translate, so this is a partial miss
rather than a whole surface.

**Required:** every one of these comes from `en`/`de`/`uk`. An `aria-label` is user-facing copy — a
screen-reader user is a user — so it is held to the same rule as visible text: no English literal,
no fallback. Where a label is a deliberate typographic mark rather than a word, say so in a comment
and give it a translated `aria-label` regardless.

## Error and edge cases

| Case | Expected |
|---|---|
| A date value with no time (`2026-09-02`) | Formatted in the app's language, still pinned to UTC as it is today — the existing `timeZone: "UTC"` behaviour must not change, or every date shifts by a day for some users |
| An invalid date string | Still rendered as a plain string, not as `Invalid Date` |
| A very large or non-finite number | Unchanged behaviour |
| A number with more than 6 fraction digits | Still capped at 6, as `NUMBER_FORMAT` does today |
| `/d/1:short` | Recognised as a damaged share link, with the truncation message |
| `/d/1` with no secret at all | Same message |
| `/d/notanumber:secret` | Not a share link; the existing "no page here" is correct here |
| `/d/1:valid` but the id does not exist | Unchanged: the existing gone message, indistinguishable from a wrong secret |
| A 64-character secret | Still accepted — T5 depends on this |
| `/view#r_articles__1` reloaded cold | Document title, not the paste title |
| `/view` with no hash | Unchanged |
| Deleting a non-last saved document | Count decrements correctly too, not only in the last-item case |
| Switching language with a document open | Every fixed string changes, including the tooltips and the `aria-label`s |

## Out of scope

- The blank **Back to the document** view. That is also pre-existing but it lives in `main.ts`, and
  T1 owns that file and is fixing it there.
- The one baseline item that could not be tested — private-window/storage-blocked behaviour. The
  harness has no incognito primitive. It stays a known gap, recorded in the QA report, not a defect.
- Any new feature. This task only makes existing behaviour correct.
- Re-theming, re-wording or re-laying-out anything that already works.

## Acceptance criteria

- [ ] With the app set to English, a date and a number in a resource attribute render in English format on a machine whose browser language is not English. Same for German and Ukrainian.
- [ ] The same holds for a date and a number in top-level `meta` and in an error's `meta`.
- [ ] No `Intl` formatter is constructed at module scope anywhere in `src/`.
- [ ] `intl.ts`'s header comment is true of the whole app, or has been corrected.
- [ ] `/d/1:short` reports a damaged link naming the expected shape, and does not say the page does not exist.
- [ ] A wrong secret and a non-existent id still produce the same message as each other.
- [ ] `/view#r_…` shows the document title; `/view` unchanged.
- [ ] The saved-documents count is right after deleting the last item and after deleting any other.
- [ ] All five string groups in D5 translate in `de` and `uk`, `aria-label`s included.
- [ ] `docs/evidence/T8.md` records a browser run at the branch-head SHA it was performed at, **with the browser's own language set to something other than the app's** — that is the only configuration in which D1 is visible at all.

## Tests that must exist

- [ ] `formatDate` and `formatNumber` produce the German and the Ukrainian rendering when the app's language is German and Ukrainian, asserted against expected strings rather than against `toLocaleString()` — a test that calls the same API it is testing cannot fail.
- [ ] A date-only value stays on its UTC day in all three languages. This is the regression that would otherwise ship silently.
- [ ] A grep-style test asserting no `new Intl.` at module scope in `src/`, so this cannot come back.
- [ ] `parseRoute` for `/d/1:short`, `/d/1`, `/d/1:` and `/d/notanumber:secret`, each to the stated outcome.
- [ ] The damaged-link message and the wrong-secret message are asserted **not** to distinguish existence.
- [ ] `test/seo.test.ts`: `/view` with a hash and without both describe the document.
- [ ] The library count after deleting the last entry, and after deleting one of several.
- [ ] An i18n completeness test covering the D5 keys in all three catalogues — the type system already catches a missing key, so this test's job is the `aria-label`s and anything read through a non-`t()` path.
