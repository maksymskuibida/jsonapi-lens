# Task specification — T1: Plain JSON

> The contract the implementer builds to, the reviewer checks against, and QA verifies from.
> Contract level, not line level.

## Outcome

Any JSON can be read, not only a JSON:API document. Two things change for a user: a payload that is
not JSON:API is **named** and offered rather than refused, and once read, **repeated identifiers
become links** the way `{type, id}` pointers already do — so clicking `user_id: 42` lands on the
object that defines `id: 42`.

That second half is the point. A generic tree view is a commodity; this tool's actual feature is
resolving identity, and JSON:API merely *declares* the graph that most payloads only imply.

## Interface

A `Lens` discriminated union is what the view layer consumes:

```
Lens = { kind: "jsonapi"; index: DocumentIndex }
     | { kind: "json";    index: JsonIndex }
```

`DocumentIndex` is **unchanged**. The JSON:API path must not regress, so nothing in `parse.ts`'s
existing output shape moves.

`JsonIndex` carries: the parsed root; the detected `shape`; `collections` (the rail's input);
`identities` (value → where it is defined and where it is referenced); `dangling` (referenced,
never defined); and the same `counts` shape the overview already renders.

**The anchor scope table is part of this task.** [D1](../DECISIONS.md) defines the scheme but no
code implements it yet: `src/ident.ts` has a single `const PREFIX = "r_"`, and `g_` is minted by
string concatenation at `src/render-document.ts:18`. T1 is the first task to add a scope (`n_`, for
a plain-JSON node), so it also:

- introduces the `AnchorScope` union and the exhaustive scope table in `src/ident.ts`, as D1
  describes;
- moves `groupDomId` onto it, so `g_` is no longer concatenated outside `ident.ts`;
- adds every test D1 names — including the assertion that all scope first-characters are distinct,
  which is what makes the cross-scope proof true rather than merely asserted;
- covers the flank the proof does not: **no static id in `index.html`, and no id minted anywhere
  else, may begin with a scope letter followed by `_`**, or it could shadow a real anchor.

`detectShape(text)` returns one of `jsonapi` · `hal` · `odata` · `jsonrpc` · `envelope` ·
`collection` · `ndjson` · `plain`, with the evidence that decided it. It never throws. It takes the
raw text, not a parsed value: every shape but `ndjson` is a structural fact about one parsed JSON
value and could be decided from that alone, but a stream of JSON Lines is not valid JSON as a whole
document, so the only way to recognise it is to still be holding the original text once the ordinary
parse has failed — see `src/shape.ts`'s own header for the full reasoning.

## Behaviour

**Shape detection replaces the hard refusal.** `assertJsonApi` currently throws when there is no
`data`, `errors` or `meta`. That failure becomes the branch point: the paste view names the shape it
found and offers *Read as plain JSON*, keeping *Read as JSON:API anyway* available for a near-miss
document. A document that **is** JSON:API still goes straight through with no extra click.

**Collections.** An array of two or more objects sharing a majority of their key names is one
collection, named by its JSON Pointer (`/data/users`). Collections drive the existing rail —
counts, hues, sigils, proportion bars, solo filter — with no new rail code. A collection is
anchored, and so is each of its members.

**The identity graph.** One pass collects candidate identifiers:

- any scalar at a key matching `id`, `uuid`, `guid`, `key`, `code`, `ref`, `slug`, or `*_id` /
  `*Id` / `*_ids` / `*Ids` (case- and separator-insensitive);
- any string anywhere matching a UUID, ULID or 24-hex-character ObjectId, since those are
  identifiers wherever they appear.

A value is an **identity** when it occurs two or more times. Its **definition** is an occurrence at
a bare `id`-like key on an object; every other occurrence is a **reference** and renders as a link
to the definition.

**Inference must never lie**, and this is the rule that matters most:

- A numeric or short-string value only matches when the reference key *names* the definition's
  container — `user_id` → a collection whose pointer ends `users`/`user`, singular or plural. A bare
  `1` matching every `id: 1` in the document is a wrong link, and a wrong link is worse than none.
- UUID/ULID/ObjectId values are globally unique by construction, so they match on value alone.
- **More than one candidate definition renders as ambiguous** — shown, counted, not linked — never
  resolved by picking the first.
- A reference with no definition is **dangling**, and feeds the panel that already exists for it.

## Error and edge cases

| Case | Expected |
|---|---|
| Valid JSON:API | Read as JSON:API, no prompt, no behaviour change of any kind |
| `{}` | Shape `plain`, zero collections, zero identities; overview says the document is empty |
| A bare array of objects | Shape `collection`; today this is a hard error |
| A bare array of scalars | Shape `collection`, one collection, no identities |
| A bare scalar or `null` | Read, rendered as one value; not an error |
| `{"data": 1}` | Shape `envelope`; today this passes `assertJsonApi` and renders zero resources with no explanation |
| `data` **and** `errors` present | Still refused as invalid JSON:API, still offered as plain JSON |
| HAL (`_links`, `_embedded`) | Shape `hal`; `_links.*.href` rendered as links, `_embedded` members as collections |
| OData (`@odata.context`, `value`) | Shape `odata`; `value` is the primary collection |
| JSON-RPC (`jsonrpc`, `error`) | Shape `jsonrpc`; `error` feeds the errors panel |
| NDJSON / JSON Lines | Shape `ndjson`; one collection of *n* records. A trailing newline and a blank line are tolerated; one malformed line reports its line number and reads the rest |
| Deeply nested (200+ levels) | Read without stack overflow — the walk is iterative, not recursive |
| A cyclic structure | Impossible from `JSON.parse`; no cycle handling required, and none should be written |
| 50 MB / 200k nodes | Identity pass respects a budget analogous to `REVERSE_POINTER_LIMIT`; over it, inference is skipped and the overview says so rather than stalling |
| Same value defined twice at `id` | Ambiguous: rendered, counted, not linked |
| `user_id: 42` with no `users` collection | Dangling |
| `id` whose value is an object or array | Not an identity candidate |
| Emoji, `__`, `#`, `/` in a key used for an anchor | Encoded through `ident.ts`; no duplicate DOM id |

## Out of scope

- Any request handling — that is T2.
- Editing, filtering or querying the JSON.
- Schema inference or type generation.
- A second render path: plain JSON reuses `render-value.ts` as it is.
- Cross-document identity (matching ids between two pasted documents).

## Acceptance criteria

- [ ] A valid JSON:API document reads exactly as it does today: same resources, same anchors, same overview, same rail.
- [ ] Pasting `{"data": 1}`, a bare array, and an NDJSON stream each produce a readable document rather than an error.
- [ ] The paste view names the detected shape and offers both readings when the document is not JSON:API.
- [ ] In plain-JSON mode, a reference to a defined identifier is an `<a>` whose target element exists in the DOM.
- [ ] A reference with no definition is shown as absent, and counted in the overview.
- [ ] An identifier with two candidate definitions is shown as ambiguous and is **not** a link.
- [ ] The rail lists inferred collections with counts and works with the solo filter.
- [ ] Every new user-facing string exists in `en`, `de` and `uk`.
- [ ] `docs/evidence/T1.md` records a browser run at the branch-head SHA it was performed at.

## Tests that must exist

- [ ] `detectShape` returns the right shape for each row of the table above, including the evidence it used.
- [ ] Every existing test in `test/parse.test.ts` and `test/render.test.ts` still passes unmodified — the JSON:API path is not touched.
- [ ] `user_id: 42` links to `/users/2` when a `users` collection defines `id: 42`; and does **not** link when the only `id: 42` is in an `orders` collection.
- [ ] A UUID referenced from an unrelated key still links, because UUIDs match on value alone.
- [ ] Two definitions of one identifier produce an ambiguous entry and no `<a>`.
- [ ] A 200-level-deep document is indexed without a stack overflow.
- [ ] Hostile values (`<img src=x onerror=…>`, `"><script>`, `javascript:` at a key rendered as a link) appear as text; the `javascript:` URL is not an `href`.
- [ ] No two anchors in a rendered plain-JSON document share a DOM id, over a corpus of keys containing `_`, `__`, `#`, `/` and emoji.
