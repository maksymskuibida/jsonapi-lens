# Task specification — T6: Share a bundle from the saved list

> Contract level, not line level. Depends on **T5** (the version-3 bundle payload). Independent of
> T1–T4.

## Outcome

One link can carry several saved documents. In the saved list you press **Share**, tick the
documents you want, and get a link. Opening that link offers its documents for import — all of
them, a selection, or none.

The saved list is where documents you deliberately kept already live, so it is the right place for
this: the selection is the list you are already looking at.

## Interface

No new module is required; this is the library panel plus a route destination.

- `openLibraryModal` gains a **selection mode**. In list mode it behaves exactly as it does today.
- A new **bundle import view**, reached when `/d/<id>:<secret>` decrypts to a version-3
  `BundlePayload`.

## Behaviour

### Selection mode

| | |
|---|---|
| **Entering** | A `Share` button in the library's footer. Absent when the library is empty — there is nothing to select. |
| **In selection mode** | Every row gains a checkbox. The row's own Open / Rename / Delete controls are hidden, because in this mode a click on the row means "select", and two meanings for one click is how people lose a document. |
| **The buttons change** | `Share` and the usual footer controls are replaced by `Cancel` and `Create link`. |
| **`Create link` is disabled while nothing is ticked**, and says why — a disabled control with no reason is a dead end. |
| **One ticked** | Mints a **single-document** share: envelope version 2, byte-for-byte the share that exists today. Not a one-entry bundle. |
| **More than one ticked** | Mints a **bundle**: envelope version 3. |
| **`Cancel`** | Returns to list mode with the modal still open and the selection discarded. |
| **`Escape`** | Returns to list mode, and does **not** close the modal — the first Escape undoes the mode you just entered, which is the smaller step. A second Escape closes the modal, as it does today. |

`Create link` hands off to the **existing** share modal — the lifetime picker, the copy button, the
"nothing leaves your browser unless you press this" framing. Do not build a second one.

Where any selected document carries an exchange holding a secret or a personal datum, the share
modal's existing redaction offer covers the whole bundle, with a count across all of it. Redaction
is per-link, never partial-per-document — one link, one decision.

### The bundle import view

Reached when a share link decrypts to a bundle. It replaces the document view for that load; it is
not a modal, because it is where the URL landed.

- Lists every document in the bundle: label, size, and the shape summary already computed for
  library rows (`data[2]`, and so on).
- **Every row starts ticked**, because the common case is "someone sent me these, I want them".
- `Import selected` writes the ticked documents to the library. `Cancel` discards and goes to the
  paste view.
- A document whose text is **byte-identical** to one already in the library is marked *already
  saved* and starts **unticked**. Ticking it imports a second copy — that is a legitimate choice,
  not an error, so it is allowed and labelled.
- After import: say how many were saved, and offer to open one. Do not silently open one — the user
  asked to import, not to navigate.
- **The secret must not be left in history.** The existing share flow replaces the entry after
  loading for exactly this reason; a bundle does the same, before the import view renders.

## Error and edge cases

| Case | Expected |
|---|---|
| Empty library | No `Share` button at all |
| One document in the library | `Share` works; one tick, a single-document link |
| Tick, then untick everything | `Create link` returns to disabled, with its reason |
| Delete or rename while in selection mode | Not reachable — those controls are hidden in this mode |
| A ticked document deleted in another tab, then `Create link` | The missing document is reported by label and dropped from the selection; the rest still links |
| Selection exceeding the 12 MB ciphertext cap | Refused before upload, naming the largest documents and the overage, so the next action is obvious |
| The share upload fails | The existing share error, and **the resolved selection is preserved** — retrying (clicking `Create link` again, in the same share dialog) re-mints the same documents without needing to reopen the library and re-tick anything. Amended by PR #5 review (S6): the library dialog itself is not kept open behind the share dialog — `openModal` replaces one dialog with the next, per this task's own "hand off to the existing share modal… do not build a second one" — so *selection mode* is not what survives, the *already-resolved list of documents* is, captured once in the retry closure before the first attempt |
| Storage blocked (private window) | The library is empty, so no `Share` button. Consistent with today |
| A bundle link opened with the wrong secret | The existing decryption failure. No hint that it was a bundle — that would be an oracle |
| A version-2 blob crafted with an extra `kind: "bundle"` field (valid `text`, so it passes version-2 validation, and satisfies `isBundlePayload`'s `.kind` check too) | The same readable "that shared bundle is corrupt" error a genuinely malformed bundle gets — never a blank page. Added by PR #5 review (B1): confirmed reachable by anyone, since the sender picks both the content and the secret |
| A version-3 link opened by an older build | T5's wrong-version error. Not this task's problem, but do not paper over it |
| A bundle of one entry (hand-made, or from another client) | Opens in the import view normally |
| A bundle entry whose text is not valid JSON | Imports fine, and fails to parse when opened — with the per-document error. The bundle is a carrier, not a validator |
| Two entries with the same label | Both imported, both listed. Labels are not identities |
| A label containing markup or an emoji | Rendered as text, and it must not break the row |
| Import with storage blocked | Reports that nothing could be saved rather than claiming success |
| 50 documents in one bundle | The import list scrolls inside its own container; the page body never scrolls sideways |
| Keyboard only | Enter selection mode, move between checkboxes, toggle with Space, reach `Create link`, all with a visible focus ring |

## If you add an IndexedDB object store, you inherit an untested path

You should not need one — a bundle is a link, and its documents land in the existing `library`
store. But if you conclude you do:

**The "create a store during an upgrade" branch in `src/store.ts` has zero test coverage.** This is
demonstrated rather than suspected: PR #1's reviewer made `library` creation conditional on
`oldVersion === 0` and all 230 tests still passed. T5's new test covers the *guarded* path — a
destructive migration is caught — but nothing exercises a store being created by an upgrade. So
adding a store means also adding that coverage, in the same change, or the next `DB_VERSION` bump
silently ships a broken upgrade for anyone whose database predates it.

Say in your PR body whether you added a store. "No" is the expected answer and the better one.

## Out of scope

- Any change to the envelope, the payload shapes, or the Worker — **T5** owns those, and this task
  must not need to touch them.
- Sharing the currently-open document. That button already exists and is unchanged.
- Bundling anything that is not in the library (the current document, a file on disk).
- Editing a bundle after it is minted, or revoking one.
- An MCP-facing surface — **T7**.

## Acceptance criteria

- [ ] `Share` reveals a checkbox on every row and replaces the footer with `Cancel` and `Create link`.
- [ ] `Create link` is disabled with nothing ticked, and states why.
- [ ] One tick produces a link that an **unmodified previous build** can open — the single-document path must not have become a bundle.
- [ ] Several ticks produce a link that opens the import view listing exactly those documents.
- [ ] `Import selected` saves them to the library, reports the count, and offers to open one without doing it unasked.
- [ ] A duplicate of an already-saved document is marked and starts unticked.
- [ ] `Cancel` in selection mode restores the list with the modal open; `Escape` does the same, and only a second `Escape` closes.
- [ ] After a bundle loads, the secret is not in `location` and not in the history entry.
- [ ] A failed upload preserves the resolved selection well enough to retry without re-opening the
      library and re-ticking — see the amended error-table row above for what that means in practice.
- [ ] Every new string exists in `en`, `de` and `uk`.
- [ ] `docs/evidence/T6.md` records a real browser run of the full round trip — select, create, open the link, import — at the branch-head SHA it was performed at, in both themes and at 375px.

## Tests that must exist

- [ ] Selecting one document produces a version-2 payload; selecting two produces version-3. Asserted on the sealed bytes' version byte, not on a variable.
- [ ] The disabled state of `Create link` is a function of the selection count: 0 disabled, 1 enabled, n enabled.
- [ ] A selection whose sealed size exceeds the cap is refused, and the message names the largest documents.
- [ ] A ticked id that no longer exists in the library is dropped, reported by label, and does not abort the rest.
- [ ] Duplicate detection is on exact text, not on label: same text different label is a duplicate; same label different text is not.
- [ ] Import writes exactly the ticked entries, and writes nothing when storage rejects.
- [ ] A label containing `<img src=x onerror=…>` renders as text in both the selection row and the import row.
- [ ] Browser scenario: after a bundle import, Back and Forward still restore the paste and import views without the secret reappearing in the URL.
