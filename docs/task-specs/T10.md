# T10 · The test suite must not depend on the runner's language

**Status:** 🔨 · **Kind:** defect fix (pre-existing, found by a contributor on a German machine)

## The defect

Node has shipped a built-in `navigator` since v21 whose `language`/`languages` reflect the host's
locale environment. `src/crypto.ts` reads every refusal through `t()`; `t()` asks `locale()`; and
`locale()` negotiates `?lang=` → `localStorage` → `navigator.languages` → English.

That third step is the trap. On a machine whose locale is German or Ukrainian — **the two languages
this app itself ships** — `locale()` resolved to `de`/`uk`, and assertions like
`rejects.toThrow(/corrupt/)` met `"Dieses geteilte Dokument ist beschädigt."`.

Measured on `main` at `7fdd2b0`:

```
LANG=de_DE.UTF-8 LC_ALL=de_DE.UTF-8 npx vitest run
→ Tests  5 failed | 608 passed (613)
```

Only `test/crypto.test.ts` runs under `@vitest-environment node`, where `navigator` is Node's own;
under jsdom it is jsdom's, which is always `en-US`. So this is a property of the environment, not of
those five assertions.

## The interface

A pin in `test/setup.ts`, wired through `setupFiles` in `vitest.config.ts`, writing `"en"` to
`STORAGE_KEY` before any test runs — the `stored()` step `locale()` consults **before** `navigator`.

- `STORAGE_KEY` is exported from `src/i18n/index.ts` rather than spelled out, so a rename cannot
  silently unpin the suite.
- The pin writes, reads back, and installs an in-memory storage if the two disagree. The property
  held is *"the pin took effect"*, not *"this environment has a working `localStorage`"*: Node has
  none by default but grows one under `--experimental-webstorage`, jsdom can be configured without
  one, and a storage that silently keeps nothing is indistinguishable from one that works.
- `setupFiles` is what guarantees ordering — `locale()` memoises on first call.

## Out of scope, and named rather than left to be found

- **Restoring the Node-types boundary.** `test/locale-probe.mjs`'s header used to claim the tsconfig
  covering `src` carries no Node types, so nothing under `src/` could reach a Node API and
  typecheck. That has not been true since the `mcp/` tree brought `@types/node` in as a
  devDependency: a file under `src/` importing `node:child_process` typechecks clean today. The
  false claim is corrected in this task; **re-establishing the boundary is its own task.**
- **`test/panels.test.ts`'s load flake** (`a ticked document deleted from another tab is dropped and
  named`), which waits on a fixed `setTimeout(resolve, 20)`. Pre-existing, unrelated to locale — it
  fails with an *empty* toast, not a German one — and seen once in four full runs under `LC_ALL=C`.
- Changing how `locale()` negotiates in the **app**. The production order is correct; only the test
  environment was ambiguous.

## Acceptance criteria

1. The whole suite passes under a German, a Ukrainian, an English and a `C` host locale.
2. The pin is load-bearing: changing it to pin `"de"` turns `test/crypto.test.ts` red.
3. `test/mcp/locale-pin.test.ts`'s positive control passes regardless of the runner's own `LC_ALL` —
   including `C`, which CI uses.
4. No source file under `src/` changes behaviour; `src/i18n/index.ts` gains an export and a comment.
